# 多周期技术面解释规则

## 周期职责

默认面向非日内、周度或月度调仓：

1. **月线是主结构。** 判断长期趋势、最后一笔方向、主要重叠区间和价格所处位置。
2. **周线是仓位节奏。** 判断月线结构是否被确认、修复或背离，辅助分批增减仓。
3. **日线是执行层。** 只判断短期是否过热、跌破或出现更合适的执行窗口，不反转月线主结论。

只有三个周期的数据截止日都清楚、质量门通过时，才能声称“多周期共振”。周期冲突必须直接写出。

## CZSC 结构

- 使用 CZSC 公共接口生成 `RawBar` 和 `CZSC` 对象。
- “笔方向”指最后一个已完成笔的方向，不等于未来走势。
- “有效三笔重叠区间”由最近三笔构造 `ZS` 并通过有效性检查；没有有效区间时写“未识别”，不得强行命名中枢。
- 未完成段只作为当前价格相对最后已完成笔端点的描述，不视为已确认笔。
- 周线和月线由已完成日线本地合成，时间戳使用该周期最后一个实际交易日。
- 当前周/月聚合 K 可能尚未完成；只把 CZSC 已完成笔用于结构确认，并在报告中披露该限制。

## chan.py 双参数结构

- 同一归一化前复权 K 线并行送入 CZSC 与 chan.py；禁止 chan.py 自行联网取数。
- chan.py 同时运行固定的 `strict` 与 `broad` 参数。输出完整笔、线段、线段的线段、中枢、线段中枢和 BSP，并逐项标记 `confirmed` 或 `provisional`。
- BSP 类型保留上游规范 `1`、`1p`、`2`、`2s`、`3a`、`3b`，只描述为上/下转折结构候选，不命名为可执行买卖信号。
- 稳定结构是两组参数的语义交集。笔数、线段数或中枢数不同只记差异，不因此单独判为 `disputed`。
- 引擎一致性比较双方最后已确认笔的方向与端点日期等可比锚点。关键月/周方向相反才可判 `disputed`；方向一致但端点差异较大可判 `degraded`。
- state 记录每个结构元素的 `first_seen`、`last_changed` 与 `withdrawn`。provisional 元素后续消失时必须保留撤回记录。
- `confirmed` 只表示当前 `technical_as_of` 下引擎确认，不表示追加 K 线后不可修订。prefix/full 复现可出现已确认笔端点延长、已确认笔消失及 BSP 撤回；confirmed 与 provisional 都必须进入生命周期比较。
- BSP 无论所属笔当前是否 `is_sure`，都只称中性形态候选，不升级为交易信号。

## 周期父子上下文

- 从同一批日 K 本地形成月→周、周→日父子映射；不把三个周期当成互不相关的独立序列。
- 用跨参数稳定且已确认的中枢描述父子价格区间为 `child_inside_parent`、`child_contains_parent`、`overlap` 或 `disjoint`。
- 缺少父级或子级稳定中枢时写 `unavailable`；区间嵌套只作结构上下文，不产生方向信号。

## 辅助指标

均线、ATR 和量能只用于确认或反证结构：

- `close > MA20 > MA60` 可描述为中期趋势偏强；反序偏弱；其余为混合。
- MA120 仅在样本足够时使用。
- ATR14 表示波动背景，不单独产生方向。
- 量比为最后一根成交量相对前 20 根均量；数据不足时留空。
- 近 20 根收益率用于描述动量，不等同于预期收益。

## 静态图解释

- 按月线主结构、周线仓位节奏、日线执行窗口的顺序阅读 chan.py 原生图，不用日线图反转月线结论。
- 只把 `strict` profile 画入原生图；从结构化结果读取 strict/broad 语义交集和差异，不根据两张重叠图肉眼判断稳定性。
- 默认显示 K 线、合并 K 线、笔、线段、线段的线段、中枢、线段中枢、BSP、线段 BSP 与 MACD。把实线/虚线分别理解为当前截止日下的 confirmed/provisional 显示，不把任何线型解释成未来确定性。
- 将 BSP 和线段 BSP 一律称为中性形态候选。不得使用“买入”“卖出”“开仓”或“止损”解释图中上游标记。
- 保持图片为静态、非动画、非交互产物。不要调用 chan.py 的动画驱动或 A 股 GUI；若需要交互式 HTML，应另行设计并重新验证证据与哈希合同。
- 核对三张原生图与报告使用同一 normalized input digest、pinned commit 和 strict `config_hash`，并从 analysis manifest 核对每张图的 SHA-256。
- 将 `--no-native-chan-charts` 解释为只禁用原生三图，将 `--no-audit-chart` 解释为禁用全部静态图。不要把显式 `not_generated` 当作分析失败。
- 将渲染失败限制在可视化产物状态；继续使用可验证的结构化结果，并披露缺失周期和失败原因。若结构化结果本身也失败，再按引擎质量门降级。

## 仓位语言

允许：

- “月线结构偏强，周线确认，日线仅用于等待回撤后的执行窗口。”
- “月线未转强，周线修复但不构成长期趋势反转证据。”
- “数据或周期冲突，只支持维持观察/缩小决策幅度。”

避免：

- “必涨”“确定买点”“满仓”“止损后一定反弹”；
- 将日线单一形态覆盖基本面、估值或重大 Event；
- 将笔、中枢或均线直接等同于投资回报。

## 默认失效条件

至少列出：

- 新完成的月线或周线笔改变当前方向；
- 价格有效跌破/突破报告中的有效重叠区间；
- 新除权除息数据导致复权历史重算；
- 双源差异扩大或行情截止日失效；
- 基本面、治理、监管或重大 Event 改变投资论点。

## Markdown 输出顺序

1. 范围、截止日与数据质量；
2. 面向周/月调仓的直接结论；
3. 月线、周线、日线表；
4. CZSC 结构与辅助指标；
5. 周期冲突、证据分类与失效条件；
6. 双引擎一致性、参数稳定交集、结构生命周期、综合审计图，以及 strict 原生月/周/日静态图及其 manifest/SHA-256；
7. 基本面/估值/事件仍需补齐的缺口。
